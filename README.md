# 🎁 SteamGift — автовыдача Steam-гифтов через DesslyHub

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayCardinal) **v0.1.17+**

**Автор:** yungspider

Покупатель оплатил лот «Steam Gift: <игра>» — плагин сам берёт его ссылку «добавить в друзья»,
покупает игру-гифт через API [DesslyHub](https://desslyhub.com/ru) и следит за транзакцией до
статуса `success` / `failed`. Вам остаётся пополнять баланс DesslyHub и читать уведомления.

## Как это работает

```
новый заказ FunPay
      ↓
привязка лота: «Steam Gift Cyberpunk 2077» → app_id 1091500
      ↓
ссылка «добавить в друзья» + регион (из полей заказа / описания / запроса в чате)
      ↓
проверки: баланс DesslyHub, лимит цены гифта, минимальная маржа, ЧС
      ↓
GET  /service/steamgift/games/{app_id}   → издание (package_id) и цена региона
POST /service/steamgift/sendgames        → transaction_id (reference = номер заказа)
      ↓
GET  /merchants/transaction/{id}/status  → pending → success / failed / cancelled
      ↓
success → покупателю «примите подарок» · failed → критический алерт продавцу
```

## Возможности

- 🎁 **Полный цикл по API DesslyHub**: каталог игр → издание и цена региона → отправка гифта →
  опрос статуса транзакции до финала.
- 🧪 **DRY-RUN по умолчанию** — весь сценарий проходит, но покупка **не совершается**: можно
  спокойно настроить привязки и проверить их на реальном заказе, не потратив ни цента.
- 🔗 **Ссылку «добавить в друзья» ищет сам**: в полях заказа (названия полей настраиваются),
  в описании, а если её нет — вежливо просит покупателя в чате и ждёт `wait_link_minutes`
  (ссылка из сообщения подхватывается автоматически, регион — тоже).
- 🎮 **Привязки лотов в меню**: поиск игры по каталогу DesslyHub (показывает `appid`),
  добавление/удаление привязок, издание и регион для каждого лота.
- 🛡 **Защита денег**: лимит цены одного гифта, порог баланса DesslyHub, минимальная маржа
  (цена заказа FunPay переводится в $ по курсу DesslyHub), проверка черного списка,
  **ровно одна покупка на заказ** — даже при дублях событий и перезапусках.
- ⚠️ **Понятные ошибки по-русски**: `-51` битая ссылка, `-55` игра уже есть, `-58` регион
  недоступен, `-59` покупатель не добавил бота в друзья, `-2` недостаточно средств — и т.д.
- 🔁 **Сетевые сбои ретраятся**, бизнес-ошибки — нет (деньги не тратятся дважды).
- 💾 Состояние очереди и транзакций на диске: перезапуск Кардинала не теряет заказы, а оборванная
  отправка **не повторяется автоматически** (заказ передается вам — двойная покупка опаснее).
- 📋 Меню `/gift`: баланс, привязки, транзакции, лимиты, тексты сообщений, тест подключения.

## Установка

```bash
cd /home/fpc/FunPayCardinal
wget https://raw.githubusercontent.com/yungspiderq/FPC-SteamGift/main/steam_gift.py -O plugins/steam_gift.py
sudo systemctl restart FunPayCardinal@fpc
```

или отправьте файл боту в Telegram → `🔌 Плагины` → `➕ Добавить плагин`.

> ⚠️ Лоты с гифтами **не должны** быть в `configs/auto_delivery.cfg` — иначе Кардинал выдаст
> товар сам, вместе с гифтом.

## Первый запуск (по шагам)

1. `/gift` → **🔑 API-ключ** — ключ выдаёт менеджер DesslyHub
   ([@DesslyHub_Manager](https://t.me/DesslyHub_Manager), partner@desslyhub.com).
2. **🧪 Тест подключения** — покажет баланс, размер каталога и проверит все привязки.
3. **🎮 Привязки лотов → 🔎 Найти игру в каталоге** — введите название, получите `appid`.
4. **➕ Добавить привязку** в формате `название лота | app_id | издание | регион`, например:
   ```
   Steam Gift Cyberpunk 2077 | 1091500 | Cyberpunk 2077 | RU
   ```
   Издание и регион можно не указывать (регион возьмётся из заказа или из `default_region`;
   издание обязательно, если у игры их несколько).
5. Сделайте **тестовый заказ** своего лота, оставив **DRY-RUN включенным**: в Telegram придет
   карточка «что было бы куплено» — игра, издание, регион, цена, ссылка покупателя.
6. Проверьте, что цена и регион верные, и только затем **выключайте DRY-RUN** и включайте плагин.

## Использование

Команда **`/gift`** (или `⚙️ Настройки` на странице плагина):

| Кнопка | Действие |
|---|---|
| 🔴 Включить / 🟢 Выключить | Master-switch автовыдачи гифтов |
| 🧪 DRY-RUN: ВКЛ/ВЫКЛ | Тестовый режим: всё считается, но покупка не совершается |
| 🔑 API-ключ | Ввести ключ DesslyHub (в меню показывается маскированным) |
| 💳 Баланс | Текущий баланс мерчанта DesslyHub |
| 🧪 Тест подключения | Баланс + каталог игр + проверка всех привязок лотов |
| 🔄 Проверить транзакции | Немедленно опросить статусы всех активных транзакций |
| 🎮 Привязки лотов | Список, ➕ добавление, 🔎 поиск игры по каталогу, 🗑 удаление |
| 🧾 Транзакции | Последние заказы: статус, игра, цена, текст ошибки |
| 🛡 Лимиты и защита | Лимит цены, порог баланса, маржа, код валюты, ожидание ссылки |
| 💬 Тексты сообщений | Текст запроса ссылки, текст после успеха, текст при ошибке |

### Тексты по умолчанию

Запрос ссылки (если её нет в заказе):

```
Здравствуйте, $username! Спасибо за покупку 🎁
Чтобы отправить игру-гифт, пришлите, пожалуйста:
1) ссылку «добавить в друзья» из вашего профиля Steam (Steam -> Профиль -> Друзья ->
   Добавить друга -> отправить ссылку-приглашение);
2) регион вашего аккаунта Steam (например: RU, KZ, UA, US).
```

После успешной отправки:

```
🎁 Игра отправлена вам в подарок! Примите подарок в Steam в течение 24 часов
(Steam -> Уведомления или Инвентарь -> «Принять подарок»).
Спасибо за покупку, $username! Будем рады вашему отзыву ⭐
```

Во всех текстах работают переменные Кардинала (`$username`, `$order_desc`, `$full_date_text`, …)
и `$order` (номер заказа), `$game` (название издания). При ошибке покупателю по умолчанию
**ничего не отправляется** — разбирается продавец (`failed_text` пустой).

## Настройки

`storage/plugins/steam_gift/settings.json` — можно править руками (перечитывается при каждом
обращении) или через меню `/gift`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | master-switch: обрабатывать ли заказы |
| `dry_run` | `true` | тестовый режим — покупка не совершается |
| `apikey` | `""` | API-ключ DesslyHub |
| `base_url` | `https://desslyhub.com/api/v1` | адрес API |
| `timeout` / `retries` | `20` / `2` | таймаут запроса и число повторов при сетевом сбое |
| `default_region` | `RU` | регион, если он не указан в привязке и не найден в заказе |
| `invite_field_names` | список | по каким названиям полей искать ссылку покупателя |
| `region_field_names` | список | по каким названиям полей искать регион |
| `ask_for_link` | `true` | просить ли ссылку в чате, если её нет в заказе |
| `ask_link_text` | см. выше | текст запроса ссылки |
| `wait_link_minutes` | `60` | сколько ждать ссылку от покупателя |
| `success_text` | см. выше | сообщение покупателю после успешной отправки |
| `failed_text` | `""` | сообщение покупателю при ошибке (пусто = не отправлять) |
| `poll_interval` | `10` | интервал опроса статусов транзакций, секунд |
| `poll_max_minutes` | `90` | после этого транзакция считается «зависшей» → алерт |
| `min_balance_usd` | `5` | порог баланса DesslyHub (ниже — не покупаем + алерт) |
| `max_order_cost_usd` | `100` | лимит цены одного гифта (защита от ошибки в привязке) |
| `min_margin_percent` | `0` | минимальная маржа, `0` = проверка выключена |
| `funpay_currency_code` | `5` | код валюты цены заказа (5 RUB, 1 USD, 3 EUR, 18 UAH, 37 KZT) |
| `notify_success` / `notify_failed` | `true` | уведомления в Telegram об успехе / ошибках |
| `low_balance_cooldown` | `120` | пауза между повторными алертами о низком балансе, минут |
| `mappings` | `{}` | привязки лотов: `{ "название лота": {app_id, edition, region, package_id} }` |
| `games_cache_minutes` | `720` | время жизни кэша каталога игр |

Данные: `storage/plugins/steam_gift/orders.json` (журнал заказов и транзакций, последние 500),
`storage/plugins/steam_gift/games.json` (кэш каталога).

## Важно знать

- **Деньги.** Покупка совершается только при выключенном `dry_run` и только после всех проверок.
  На один заказ — ровно одна покупка: повторные события FunPay, повторный вызов сценария и
  перезапуск Кардинала не приводят ко второму списанию.
- **Перезапуск во время отправки.** Если бот перезапустился в момент `sendgames`, заказ помечается
  `error` («отправка прервана перезапуском») и приходит алерт: автоматически повторять нельзя —
  неизвестно, успел ли запрос дойти. Проверьте список транзакций DesslyHub (`🧾 Транзакции` или
  `GET /merchants/transactions`) и дообработайте заказ вручную.
- **Что нужно от покупателя.** Ссылка «добавить в друзья» из профиля Steam и регион аккаунта.
  Удобнее всего сделать в лоте FunPay поля «Ссылка на Steam» и «Регион» — тогда плагин возьмёт
  их из заказа и ничего спрашивать не будет. Принимаются ссылки `https://s.team/f/...`,
  `steamcommunity.com/tradeoffer/new/?partner=...`, `steamcommunity.com/id|profiles/...`
  (в том числе без `https://` — схема добавляется автоматически).
- **Ошибки покупателя.** `-55` игра уже есть, `-59` не добавил бота в друзья, `-51` битая ссылка,
  `-58` регион недоступен, `-54` нет основной игры (это DLC). Деньги при `failed`/`cancelled`
  возвращаются на баланс DesslyHub — об этом написано в уведомлении.
- **Маржа.** `min_margin_percent` сравнивает цену гифта в $ с ценой заказа FunPay, переведенной
  в $ по курсу DesslyHub (`GET /exchange_rate/steam/{код}`). По умолчанию проверка выключена —
  включите после первого тестового заказа, чтобы убедиться в направлении курса для вашей валюты.
- **Регион.** Берётся в порядке: привязка лота → поле заказа → `default_region`. Если региона
  нет в списке доступных для издания, покупка не совершается (придет понятная ошибка).
- **API-ключ** хранится только на вашем сервере в `settings.json`, в меню показывается
  маскированным, в логи не пишется и никуда не передается, кроме `desslyhub.com`.
- Плагин не трогает штатную автовыдачу Кардинала: он реагирует только на заказы лотов,
  которые вы привязали в меню.

## Используемые методы API DesslyHub

| Метод | Зачем |
|---|---|
| `GET /merchants/balance` | баланс мерчанта перед покупкой и по кнопке «💳 Баланс» |
| `GET /service/steamgift/games` | каталог игр (поиск `appid` в меню), кэшируется |
| `GET /service/steamgift/games/{app_id}` | издания (`package_id`) и цены по регионам |
| `POST /service/steamgift/sendgames` | покупка и отправка гифта (`reference` = номер заказа) |
| `GET /merchants/transaction/{id}/status` | опрос статуса до `success`/`failed`/`cancelled` |
| `GET /exchange_rate/steam/{code}` | курс для проверки маржи |

Документация: [desslyhub.readme.io](https://desslyhub.readme.io/reference/introduction),
коды ошибок: [error-codes](https://desslyhub.readme.io/reference/error-codes).

## Состав репозитория

- `steam_gift.py` — плагин (класть в `plugins/`).
- `tests_plugin_steam_gift.py` — тесты (**163 проверки** на моках: настройки и их повреждение,
  поиск ссылки и региона, привязки лотов, выбор издания, клиент DesslyHub — ретраи, бизнес-ошибки,
  битый JSON, полный цикл выдачи в DRY-RUN и боевом режиме, все денежные защиты, идемпотентность,
  черный список, запрос ссылки у покупателя и продолжение по сообщению, ошибки API (-51/-55),
  статусы failed/cancelled, восстановление после перезапуска, поллер и таймауты, весь Telegram-UI,
  удаление плагина). Запуск из корня FunPayCardinal:
  ```bash
  cp tests_plugin_steam_gift.py /path/to/FunPayCardinal/
  cd /path/to/FunPayCardinal && pip install -r requirements.txt && python3 tests_plugin_steam_gift.py
  ```
  Тесты создают настройки во временной папке — ваши реальные `storage/plugins/steam_gift/`
  не затрагиваются, запросов в интернет нет.

## Совместимость

- FunPay Cardinal **v0.1.17.x** (проверено на v0.1.17.15). Для версий 1.15.x НЕ подходит.
- Python 3.11, зависимости — только те, что уже есть в `requirements.txt` Кардинала (`requests`).
- Дружит с остальными плагинами автора; с [FPC-SalesAnalytics](https://github.com/yungspiderq/FPC-SalesAnalytics)
  и [FPC-HealthMonitor](https://github.com/yungspiderq/FPC-HealthMonitor) даст статистику и контроль
  за ботом, с [FPC-BalanceGuard](https://github.com/yungspiderq/FPC-BalanceGuard) — контроль баланса FunPay
  (баланс DesslyHub этот плагин проверяет сам).
